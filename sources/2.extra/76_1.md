# Audit Logs

The boilerplate includes a small append-only audit log pattern for security and debugging.

## Table

`supabase/migrations/0004_audit_logs.sql` creates:

```txt
<where_to_log>audit_logs
  id uuid primary key
  user_id uuid references auth.users(id) on delete set null
  action text
  entity_type text
  entity_id text
  metadata jsonb
  created_at timestamptz</where_to_log>
```

## RLS

<where_to_log>Audit logs have Row Level Security enabled.</where_to_log>

- <where_to_log>Users can select logs where `audit_logs.user_id = auth.uid()`.</where_to_log>
- <where_to_log>Users can insert logs only for their own `user_id`.</where_to_log>
- <where_to_log>No update or delete policies are created.</where_to_log>

<where_to_log>This keeps the pattern append-only for regular authenticated users. Server-only service-role code can still write operational logs when needed.</where_to_log>

## Helper

<how_to_log>Use `logEvent()` from `lib/audit/log-event.ts`:</how_to_log>

```ts
<how_to_log>await logEvent({
  action: "project.created",
  client: supabase,
  entityId: project.id,
  entityType: "project",
  metadata: {
    source: "dashboard",
  },
  userId: user.id,
});</how_to_log>
```

<how_to_log>The helper returns `{ ok, error }` and logs failures to the server console. It does not throw by default because audit logging should not usually break the main product action.</how_to_log>

## Current Events

<what_to_log>The starter logs:

- `profile.updated`
- `password.updated`
- `sessions.signed_out_others`
- `sessions.signed_out_all`
- `account.exported`
- `account.deleted`</what_to_log>

## Conventions

- <how_to_log>Use lowercase dot-separated actions, such as `project.created`.</how_to_log>
- <how_to_log>Keep `entity_type` stable, such as `project`, `user`, or `subscription`.</how_to_log>
- <what_to_log>Store only useful metadata.</what_to_log>
- <what_to_log>Do not put secrets, raw passwords, tokens, full webhook payloads, or sensitive PII in `metadata`.</what_to_log>
- <how_to_log>Add indexes only for query patterns the app actually uses.</how_to_log>
