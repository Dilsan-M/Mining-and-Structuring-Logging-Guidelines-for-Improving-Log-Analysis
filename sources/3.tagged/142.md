# AI-Nutzungs- und Projektregeln (rustyacme)

## 1. Zweck
Dieses Projekt implementiert einen RFC 8555 kompatiblen ACME v2 Server (nur HTTP-01). AI darf unterstützen (Code-Vorschläge, Reviews, Docs), aber keine sicherheitskritischen Entscheidungen final treffen.

## 2. Grundsätze
- Sicherheit vor Geschwindigkeit.
- RFC-Konformität vor Convenience.
- Keine geheimen Schlüssel oder Tokens in Commits oder Prompts.
- AI-Ausgaben werden immer menschlich geprüft vor Merge.

## 3. Erlaubte AI-Einsatzbereiche
- Refactoring-Vorschläge
- Testfall-Generierung
- Dokumentation (README, RFC_COMPLIANCE.md)
- Erstellen von Gerüsten (Module, Traits)
- Erstellen von Mocks / Stubs

## 4. Verbotene AI-Einsatzbereiche
- Generierung kryptographischer Schlüssel für Produktion
- Automatisches Akzeptieren sicherheitsrelevanter Änderungen
- Änderung von Lizenztexten
- Entfernen von Prüf- oder Sicherheitslogik
- Einbau fremder Beispiel-Zertifikate als „echt“

## 5. Code-Standards
- Rust Edition 2021
- Kein unwrap()/expect() in produktiven Pfaden (nur Tests)
- Fehler via AcmeError + Problem+JSON
- <how_to_log><log_verbosity>- Logging mit tracing (info/debug/warn/error)</log_verbosity></how_to_log>
- Jede öffentliche Funktion: klarer Return-Typ, kein impl Trait für Kern-Domain
- IDs: NewTypes (AccountId, OrderId, ChallengeId, AuthzId)

## 6. RFC-Konformität
- Antworten enthalten Replay-Nonce (außer bewusst ausgeschlossen)
- Status-Codes: 201 (newAccount/newOrder neu), 200 (Idempotenz), 204 (nonce)
- Problem+JSON Fehler (type, detail, status)
- POST-as-GET implementiert (leere JWS Payload)
- JWS Signaturprüfung (kid + gespeichertes jwk, jwk bei Kontoerstellung)

## 7. Tests
- Jede neue Route: mindestens 1 Positiv-, 1 Negativ-Test
- Signatur-Tests: gültig + manipuliert
- Nonce: Einmalige Nutzung (badNonce Test)
- Keine externen Netzwerkanfragen in Tests

## 8. Sicherheit
- Keine Persistenz = nur Demo; vor Produktivbetrieb DB/Redis + Nonce-Replay-Schutz + Rate-Limit
- Kein DNS-01 Support (bewusst ausgeschlossen)
- Keine automatische Zertifikatsausstellung mit echten CA-Schlüsseln
- CSR wird validiert bevor Zustand „valid“ gesetzt wird (ToDo falls nicht vorhanden)

## 9. Logging
- <where_to_log><how_to_log>- Request/Response Pretty Logging nur in Dev</how_to_log></where_to_log>
- <where_to_log><how_to_log><what_to_log>- In Prod: strukturiert (JSON) ohne Bodies bei sensiblen Endpoints</what_to_log></how_to_log></where_to_log>
- <what_to_log><how_to_log>- X-Request-Id wird durch Fairing gesetzt oder übernommen</how_to_log></what_to_log>

## 10. Branch / Merge
- feature/* für Implementierungen
- PR benötigt: Beschreibung + Liste geänderter RFC-Punkte
- Keine direkten Commits auf main ohne Review

## 11. AI Prompt Hygiene
- Keine vertraulichen Daten
- Keine tatsächlichen private keys oder CSR Inhalte
- Keine Real-E-Mail-Adressen außer Platzhalter

## 12. Abhängigkeiten
- Nur notwendige Crates (kein Copy-Paste von unbekannten Quellen)
- Sicherheitsupdates zeitnah
- Audits bei neuen Kryptographie-Crates

## 13. Erweiterungen (geplant, nicht umgesetzt)
- Persistenz (DB/Redis)
- Rate Limiting pro Account/IP
- OCSP / Revoke Zertifikate
- Echte Zertifikatserstellung (Integration CA)

## 14. Review-Checkliste (Kurz)
- [ ] Keine unwrap()/expect() im Produktionspfad
- [ ] Fehler nutzen Problem+JSON
- [ ] Replay-Nonce gesetzt
- [ ] JWS Signatur validiert
- [ ] Keine harten Pfade / Ports
- [ ] Tests aktualisiert
- <how_to_log>- [ ] Logging angemessen</how_to_log>

## 15. Entfernen / Bereinigen
AI-generierter Code muss entfernt oder angepasst werden, wenn:
- Unverständlich
- Nicht RFC-konform
- Performance- oder Sicherheitsprobleme erzeugt

## 16. Umgang mit Fehlern
- 401 Unauthorized: JWS/Konto Problem
- 400 Bad Request: Format / Payload Fehler
- 404 Not Found: Ressourcen-ID unbekannt
- 409 Conflict: Idempotenzverletzung (Reserviert für spätere Nutzung)

## 17. Nicht-Ziele
- DNS-01
- Wildcard-Zertifikate
- Multi-CA Betrieb
- Automatische Renewal-Logik (Client-seitig)

## 18. Änderung dieses Dokuments
Nur via PR + maintainer review. Jede Änderung bekommt eine Abschnitt-Version (SemVer im Kopf des Dokuments).
