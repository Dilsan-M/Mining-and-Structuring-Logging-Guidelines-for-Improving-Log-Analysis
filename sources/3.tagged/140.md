## Backend (Express + TypeScript)
1. **Project Scaffold**
   - Initialize a new `packages/backend` directory with `npm init -y`, TypeScript config, ESLint, and basic scripts (`dev`, `build`, `start`).
   - Install core dependencies: `express`, `pino`, `cors`, `zod`, and typings; dev deps include `ts-node-dev`, `jest`/`ts-jest`, and `supertest`.
2. **App Shell & Logging**

   - <how_to_log><what_to_log>Add centralized error handler middleware that logs structured details and returns normalized JSON errors.</what_to_log></how_to_log>
3. **Configuration & Utilities**
   - Add `src/config.ts` to read env vars (ports, upstream URLs, ISR cache TTL) via `dotenv`.
   - Implement helper modules for HTTP clients (REST + SSE) using `node-fetch`/`eventsource`, including timeout and retry logic.
4. **`/bootstrap` REST Endpoint**
   - Define `GET /bootstrap` handler that fetches README/context metadata plus upstream REST TPS/context-check info.
   - Cache the response in-memory with a 60-second TTL to align with frontend ISR expectations; expose cache headers.
   - Validate outgoing payload with `zod` to ensure shape stability.
5. **`/chat` SSE Endpoint**
   - Implement `POST /chat` that accepts `{ prompt: string }`, validates input, <what_to_log><how_to_log>assigns a trace ID</how_to_log></what_to_log>, and streams upstream SSE chunks back to the client via `res.write`.
   - Handle upstream backpressure, connection aborts, and convert upstream events into newline-delimited payloads understood by the frontend.
   - Provide heartbeat events to keep connections alive and structured error events on failure.
6. **Testing**
   - Unit-test config/validators and SSE parser utilities.
   - Integration test `/bootstrap` and `/chat` with mocked upstream REST/SSE servers (using `nock` or manual mocks) to verify streaming and caching.
7. **Tooling & Docs**
   - Create Dockerfile/compose for backend, document env vars and endpoints in `READMEs/backend.md`.
   - Add lint/test scripts to CI (if available) and usage instructions for local dev.

## Frontend (TanStack Start + TanStack Query)
1. **Project Setup**
   - Initialize `packages/frontend` via TanStack Start CLI with TypeScript and preferred styling (Tailwind/CSS modules).
   - Configure TanStack Query provider in the root layout with sensible defaults (queryClient, hydration).
2. **Data Loaders & ISR**
   - Implement a loader for the chat page that fetches backend `/bootstrap`, sets `revalidate` to 60 seconds, and prepares dehydrated TanStack Query state for fast loads.
   - Add deferred loading logic so the loader also schedules a client-side refetch without blocking initial render.
3. **Streaming Service**
   - Build a client utility (`useChatStream`) that issues a POST to `/chat`, listens to the SSE stream, and exposes callbacks for chunk arrival, completion, and errors.
   - Integrate this utility with a TanStack Query mutation so chat submissions appear in cache/history immediately.
4. **UI Components**
   - Create chat layout: message list, assistant/user bubbles, timestamp/status indicators, sticky bottom composer with textarea + send button + loading state.
   - Ensure responsive design and accessible keyboard shortcuts (Enter to send, Shift+Enter newline).
   - Show “fast load” data (from dehydrated cache) distinctly until live stream updates arrive.
5. **State Management**
   - Manage optimistic user messages and progressively updated assistant messages in React state synced with TanStack Query cache.
   - Persist session history to localStorage to survive reloads; reconcile with ISR-loaded data on mount.
6. **Error & Edge Cases**
   - Display toast/banner when the SSE stream fails, with retry controls.
   - Handle multiple concurrent prompts by queueing or disabling input while one stream is active (per product decision).
7. **Testing & QA**
   - Component tests (Vitest/RTL) for chat list and composer.
   - Mock streaming tests to verify chunk handling.
   - Document manual QA steps: verifying ISR fast load (static build + revalidate), deferred refetch, and streaming behavior against backend.
